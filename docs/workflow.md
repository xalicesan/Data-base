# Как работать с репозиторием

## Идея

В Git лежит **не сама СУБД**, а её исходники: SQL-скрипты и дамп.
База у каждого разворачивается локально из этих файлов и получается
одинаковой у всех. Общий сервер и локальная сеть не нужны.

```
Git (скрипты + дамп)  ->  у каждого свой PostgreSQL  ->  своя копия sports_db
```

## Первый запуск (каждый участник)

1. Установить PostgreSQL 17 (winget: `PostgreSQL.PostgreSQL.17`).
2. Склонировать репозиторий:

   ```powershell
   git clone <url> sports_db
   cd sports_db
   ```

3. Развернуть базу (пароль пользователя `postgres`):

   ```powershell
   .\reset_db.ps1 -PgPassword <пароль>
   ```

4. Проверить, что всё работает:

   ```powershell
   psql -U postgres -d sports_db -P pager=off -f 03_queries.sql
   ```

Если `psql` не найден, добавить в PATH: `C:\Program Files\PostgreSQL\17\bin`.

### Вариант без скриптов (из дампа)

```powershell
createdb -U postgres -E UTF8 -T template0 sports_db
pg_restore -U postgres -d sports_db release/sports_db.dump
```

Дамп — это снимок базы на момент коммита. Для работы лучше скрипты:
в них видны все изменения.

## Ежедневный цикл

```powershell
git pull                     # забрать чужие изменения
# ... работа ...
git add 03_queries.sql       # только свои файлы
git commit -m "feat(queries): запрос 9"
git push
```

Если после `pull` изменилась схема — пересоздать базу:

```powershell
.\reset_db.ps1 -PgPassword <пароль>
```

## Кто какой файл ведёт

| Файл | Владелец |
|---|---|
| `01_schema.sql` | #3 (логик/DDL) |
| `02_data.sql` | #3 |
| `03_queries.sql` | #4 |
| `04_triggers.sql` / `app/` | #5 |
| `docs/` | #1, #2 |
| `README.md`, `docs/workflow.md` | #1 (PM) |

Правило: **один файл — один владелец**. Если нужно поправить чужой файл —
сначала написать в чат, чтобы не было конфликтов.

## Изменение схемы

1. #3 правит `01_schema.sql` (при необходимости — `02_data.sql`).
2. Коммит и push.
3. Остальные: `git pull` и `.\reset_db.ps1`.
4. Пересоздание базы — нормальная практика: данные тестовые, восстановить
   их быстрее, чем писать миграции.

## Чего не делать

- не коммитить пароли, `.env`, `pgpass.conf`;
- не пушить локальные дампы, кроме `release/sports_db.dump`;
- не менять схему «по-тихому» — иначе у всех разъедется;
- не работать прямо в базе без скрипта: изменения должны попасть в Git,
  иначе их потеряют остальные.

## Сдача

- ссылка на репозиторий;
- `release/sports_db.dump`;
- пояснительная записка.

На защите база поднимается на одном ноутбуке — это нормально.

## Частые проблемы

| Симптом | Решение |
|---|---|
| `psql: command not found` | добавить `C:\Program Files\PostgreSQL\17\bin` в PATH |
| `password authentication failed` | передать `-PgPassword` или ввести пароль |
| ошибка триггера при вставке | это не баг, это правило целостности |
| «relation does not exist» | не выполнен `01_schema.sql` |
| разные версии PostgreSQL | у всех 17 |
